# Digital Legacy Vault — Infrastructure

Infrastructure-as-Code for DLV on AWS (`af-south-1` primary, `eu-west-1` DR).
Everything here is provisioned by Terraform and delivered to the cluster by Argo
CD; CI never runs `kubectl`/`helm` against a cluster (GitOps invariant).

```
infra/
  terraform/
    bootstrap/      # per-account: remote-state backend, OIDC roles, ECR (apply once)
    modules/        # reusable building blocks
      vpc/ kms/ eks/ rds-postgres/ elasticache-redis/ s3-documents/
    envs/
      dev/          # the dev "walking skeleton" stack (composes the modules)
    .checkov.yaml   # policy-scan config (used by CI)
  helm/
    dlv/            # umbrella chart (api + web)
    values/
      dev.yaml      # dev overlay; image tags bumped by GitOps
```

## 1. Bootstrap (once per AWS account)

`bootstrap/` creates the Terraform **remote-state backend** (S3 bucket
`dlv-terraform-state-<account_id>` + DynamoDB lock table `dlv-terraform-locks`,
both KMS-encrypted), the **GitHub OIDC roles**, and (in the shared/tooling
account only) the **ECR** repositories `dlv/api` and `dlv/web`.

```bash
cd terraform/bootstrap
terraform init                      # local state for this stack
terraform apply -var="environment=dev"      # per env account
# shared/tooling account also gets ECR + the push role:
terraform apply -var="environment=shared" -var="create_ecr=true"
```

Roles created (consumed by the workflows via OIDC — no stored AWS keys):

| Role | Used by | Scope |
|---|---|---|
| `dlv-gha-ecr-push` | `deploy-dev.yml` | push images to `dlv/*` only |
| `dlv-gha-terraform-plan-<env>` | `terraform.yml` (PR) | read state + plan |
| `dlv-gha-terraform-apply-<env>` | `terraform.yml` (main) | apply, behind the `dev-infra` env gate |

## 2. Environment stack (`envs/dev`)

Composes the modules into one applyable stack: **KMS → VPC → EKS → RDS → Redis →
S3 (quarantine + documents)**. Dev cost levers: single NAT, SPOT `t4g.medium`
nodes, single-AZ `db.t4g.small`, single-node Redis, CRR off.

```bash
cd terraform/envs/dev
terraform init \
  -backend-config="bucket=dlv-terraform-state-<dev_account_id>" \
  -backend-config="region=af-south-1"
cp dev.example.tfvars dev.tfvars   # then edit (CIDRs, admin role ARN)
terraform plan  -var-file=dev.tfvars
terraform apply -var-file=dev.tfvars
```

CI runs the same via `.github/workflows/terraform.yml`: PRs touching
`infra/terraform/**` get `fmt`/`validate`/`tflint`/`checkov` + a plan comment
(plan role); merges to `main` apply through the `dev-infra` environment gate
(apply role). The state bucket/region are injected at `init` time.

**Secrets never leave AWS.** RDS and Redis credentials are generated by Terraform
and stored in Secrets Manager (outputs `rds_credentials_secret_arn`,
`redis_auth_secret_arn`). Sync them into the cluster with the **External Secrets
Operator** as `dlv-api-secrets` / `dlv-web-secrets`; the chart mounts those.

## 3. Application delivery (Helm + Argo CD)

`helm/dlv` is an umbrella chart deploying **api** (NestJS, `/api/v1`, :4000) and
**web** (Next.js, :3000), both hardened (non-root, read-only rootfs, all caps
dropped), fronted by one ALB Ingress (`/api` → api, `/` → web, TLS via ACM), with
HPAs, PDBs, IRSA ServiceAccounts, and a default-deny NetworkPolicy set.

Argo CD (running in the dev cluster) tracks this repo and renders:

```
helm/dlv  +  helm/values/dev.yaml   →   dev namespace
```

An Argo CD `Application` points `path: infra/helm/dlv` with
`valueFiles: [../values/dev.yaml]` and `automated` sync (prune + selfHeal). A
`PreSync` hook runs `prisma migrate deploy` before app pods roll (app pods never
migrate).

### GitOps release loop
1. Push to `main` → `deploy-dev.yml` builds `api`+`web`, pushes to ECR tagged
   `sha-<gitsha>` (+ moving `dev`) via the OIDC push role.
2. The workflow bumps `.api.image.tag` / `.web.image.tag` in
   `helm/values/dev.yaml` and commits `[skip ci]`.
3. Argo CD detects the commit and syncs the new tag to the cluster.

In-cluster prerequisites: External Secrets Operator (for the `dlv-*-secrets`),
the AWS Load Balancer Controller (for the `alb` IngressClass), and metrics-server
(for the HPAs). IRSA role ARNs and the ACM certificate ARN are set in
`helm/values/dev.yaml`.

## Conventions
- AWS provider `~> 5.x`, Terraform `>= 1.9`; every stack sets `default_tags`
  (`Project=digital-legacy-vault`, `Env`, `ManagedBy=terraform`).
- No account IDs or secrets are hardcoded — variables and CI repo-vars only.
- Security-relevant choices are commented inline in each module.

## 4. Vault plane (Phase 3)

The document storage plane sits on the `s3-documents` module (quarantine +
documents buckets, Object Lock, SSE-KMS, CRR flag) plus KMS for envelope keys
and ClamAV/Textract for the pipeline.

### App IRSA policy
The api/worker ServiceAccounts (`api.serviceAccount.roleArn` /
`worker.serviceAccount.roleArn` in the Helm values) assume an IRSA role with a
least-privilege policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "Quarantine", "Effect": "Allow",
      "Action": ["s3:PutObject","s3:GetObject","s3:DeleteObject","s3:AbortMultipartUpload","s3:ListBucketMultipartUploads"],
      "Resource": ["arn:aws:s3:::dlv-<env>-quarantine","arn:aws:s3:::dlv-<env>-quarantine/*"] },
    { "Sid": "Documents", "Effect": "Allow",
      "Action": ["s3:PutObject","s3:GetObject"],
      "Resource": "arn:aws:s3:::dlv-<env>-documents/*" },
    { "Sid": "EnvelopeKeys", "Effect": "Allow",
      "Action": ["kms:Encrypt","kms:Decrypt","kms:GenerateDataKey"],
      "Resource": "<data-cmk-arn>" },
    { "Sid": "Ocr", "Effect": "Allow",
      "Action": ["textract:DetectDocumentText","textract:AnalyzeDocument"],
      "Resource": "*" }
  ]
}
```

Wire it as a Terraform `aws_iam_role` trusting `module.eks.oidc_provider_arn`
for the `system:serviceaccount:dlv-<env>:dlv-<env>-{api,worker}` subjects, then
put the role ARN in the per-env Helm values.

### ClamAV & OCR
- **ClamAV** runs in-cluster from the umbrella chart (`clamav.enabled`, service
  `dlv-clamav:3310`); the api/worker use `CLAMAV_HOST`/`CLAMAV_PORT`.
- **OCR** is selected by `OCR_PROVIDER` (`textract` in cloud, `tesseract`/`none`
  locally). Textract needs the IRSA policy above.

### Full-text search migration
Prisma cannot express the tsvector trigger/GIN index, so after `prisma migrate`
apply `apps/api/prisma/sql/vault-fts.sql` (idempotent) as a post-migrate step in
the Argo PreSync migration Job.
